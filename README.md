# Project 11: Infrastructure Changes with Branching Policy

## Objective
Practice Git branching and pull request workflow
for infrastructure changes.

## Branching Policy

- main: Stable infrastructure code.
- feature branches: Used for infrastructure changes.
- Changes must be submitted through pull requests.
- Review must be completed before merging.

## Infrastructure

The project uses Terraform to define an AWS VPC.

## Workflow

1. Create the main branch.
2. Create a feature branch.
3. Make infrastructure changes.
4. Commit and push changes.
5. Create a pull request.
6. Review the changes.
7. Merge the pull request.
